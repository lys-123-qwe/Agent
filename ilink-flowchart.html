长轮询消息拉取
登录成功后启动独立线程，发起 getUpdates 长轮询请求。 服务器挂起连接最多 35 秒，有消息到达立即返回，无消息则超时空返回。

每次返回 get_updates_buf（游标），下次请求带回，确保不重复消费。 过滤条件：必须有 contextToken，且至少包含文本或图片。 收到消息后提取内容，进入路由处理。

欢迎消息触发机制
因 iLink 协议不支持 Bot 主动推送消息（返回 {} 但微信侧不投递）， 欢迎语通过「消耗主人第一条消息」的方式发送。

登录后记录 ownerId（ilink_user_id）， 首次收到来自该 ID 的消息时，仅回复欢迎语（消息内容被消耗不处理）。 后续消息正常路由。

DeepSeek AI 对话机制
每个微信用户独立对话 session，存储为 ConcurrentHashMap<String, List<ChatMessage>>。 session 结构：[system, user, assistant, user, ...]。

最多保留 10 轮对话，超出后删除最早的历史（保留 system 消息）， 这是 trimHistory() 方法的作用。

★ HTTP 请求使用 byte[] 编解码，防止 Windows 控制台 GBK 乱码。 ★ Model 为 deepseek-chat（映射 deepseek-v4-flash）。

图片识别流程（CDN 下载 → AES 解密 → 通义千问 VL）

发送回复的关键细节
client_id： 每次发送必须使用不同的 UUID，微信用来去重（幂等性）。
context_token： 必须原值带回接收消息时的 token，用于关联原消息。
base_info： 包含 channel_version: '1.0.2'。
X-WECHAT-UIN： 每次请求生成新的随机数，防重放攻击。 生成逻辑：随机整数 → 无符号十进制字符串 → Base64 编码。
byte[]： Windows 默认 GBK 编码，用 byte[] 拿到原始字节再 UTF-8 解码。

★ 响应 {} 仅表示服务器接受，不代表消息已送达用户微信。 iLink 不支持 Bot 主动推送消息（无 contextToken 的请求返回 {} 但微信侧不投递）。

断开清理
polling.set(false) 使轮询循环条件不满足 → 线程自然退出。 connected.set(false) 标记连接断开。 调用 pollThread.interrupt() 中断可能的 sleep 等待。 最后清除 bot_token 使认证失效。

★ 线程标记为 daemon，程序退出时自动结束。
